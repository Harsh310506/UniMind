# Multi-Function AI Platform - Simplified Execution Plan

## **PROJECT OVERVIEW**

### **Problem Statement**

In today's information-rich environment, individuals and organizations face significant challenges in extracting actionable insights from their document collections. Users struggle with:

1. **Information Retrieval Inefficiency**: Finding specific information across multiple documents is time-consuming and often requires manual reading of entire documents.

2. **Lack of Interactive Document Intelligence**: Traditional document viewers are static and don't allow users to ask questions or have conversations about document content in natural language.

3. **Manual Assessment Creation**: Educators and trainers spend hours manually creating quizzes and assessments from educational materials, a process that is both tedious and prone to inconsistency.

4. **Fragmented Tools**: Users must switch between multiple applications for document analysis, Q&A, quiz generation, and sentiment analysis, leading to workflow disruption and context loss.

5. **Accessibility Barriers**: Documents in various formats (scanned PDFs, images, different file types) require different tools for processing, creating barriers to unified information access.

**Solution**: A unified, intelligent platform that transforms static documents into interactive knowledge sources, enabling natural language conversations, automatic assessment generation, and comprehensive document intelligence through a single, intuitive interface.

## **REVISED TECH STACK (Simplified)**

### **Frontend**
- **Framework**: React 18 with TypeScript
- **State Management**: React Context API + React Query
- **UI Framework**: Tailwind CSS + shadcn/ui components
- **Routing**: React Router v6
- **API Client**: Axios
- **Build Tool**: Vite
- **Form Handling**: React Hook Form + Zod validation

### **Backend**
- **API Framework**: FastAPI (Python 3.10+)
- **Database**: mongodb atlas
- **ORM**: SQLAlchemy 2.0
- **Authentication**: JWT with python-jose
- **File Storage**: Local filesystem (organized structure)
- **Background Tasks**: FastAPI BackgroundTasks (simple async)

### **AI/ML Stack**

**API-Based Services:**
- **Primary LLM**: Groq API
  - For conversations, quiz generation, explanations
- **Free Alternative**: Groq API (extremely fast, free tier)
  - Models: Llama 3, Mixtral, Gemma
- **Embeddings**: OpenAI Embeddings API (text-embedding-3-small)
- **Free Alternative Embeddings**: HuggingFace Inference API (free tier)

**Local Processing:**
- **OCR**: Tesseract OCR (free, open-source)
- **PDF Processing**: PyMuPDF (pymupdf)
- **Image Processing**: Pillow
- **Text Processing**: spaCy or NLTK

**Retrieval:**
- **Vector Store**: ChromaDB (embedded, no server needed)
- **BM25**: rank-bm25 library
- **Hybrid Search**: Custom implementation

**Additional Services:**
- **Sentiment Analysis**: 
  - Groq API (simple prompt-based)
  - Free: HuggingFace Inference API (distilbert-base-uncased-finetuned-sst-2)
- **Speech-to-Text**: 
  - AssemblyAI
  - Free: AssemblyAI (free tier) or Web Speech API

**Text Extraction:**
- For PDF files:

  - If not extractable, trigger OCR processing
  - Preserve page numbers and structure

    - Apply thresholding
    - Denoise if needed

  - Handle multiple languages if needed

**Text Cleaning:**
- Remove excessive whitespace
- Normalize Unicode characters
- Fix common OCR errors (if applicable)
- Remove page headers/footers (patterns)
- Preserve important formatting markers

**Text Chunking Strategy:**
- Implement semantic chunking:
  - Split by paragraphs primarily
  - Keep chunk size between 500-1000 tokens
  - Add overlap of 100 tokens between chunks
  - Preserve sentence boundaries
  - Include metadata (page number, section)
- Create chunk metadata:
  - chunk_id (sequential)
  - chunk_text
  - chunk_index
  - source_page
  - document_id
  - character_count
  - token_count (approximate)

### **PHASE 5: Vector Database & Retrieval System (Days 13-16)**

**Step 5.1: ChromaDB Setup**
- Initialize ChromaDB client with persistent storage
- Create collection with configuration:
  - Collection name: "document_chunks"
  - Metadata: document_id, chunk_index, page_number, user_id
  - Distance metric: cosine similarity
- Set up collection get-or-create pattern
- Implement collection health check

**Step 5.2: Embedding Generation Service**

**Using OpenAI Embeddings:**
- Create embedding client wrapper
- Implement batch embedding function:
  - Accept list of text chunks
  - Call OpenAI API with text-embedding-3-small model
  - Handle rate limits with retry logic
  - Return embedding vectors (1536 dimensions)
- Add embedding caching (store in memory for recently used docs)
- Implement error handling for API failures

**Alternative - Using HuggingFace (Free):**
- Use sentence-transformers library locally
- Load model: all-MiniLM-L6-v2 (384 dimensions)
- Create embedding function with batching
- Cache model in memory
- Handle device selection (CPU/GPU)

**Step 5.3: Document Indexing Service**
- Create function to index document chunks:
  - Accept document_id and list of chunks
  - Generate embeddings for all chunks
  - Prepare metadata for each chunk
  - Insert into ChromaDB with unique IDs
  - Handle batch insertion (100 chunks at a time)
  - Update document status to COMPLETED
- Add error handling and rollback mechanism
- Implement index verification (count check)

**Step 5.4: Vector Search Implementation**
- Create semantic search function:
  - Accept query text and optional document filter
  - Generate query embedding
  - Search ChromaDB with:
    - Top K results (default 10)
    - Minimum similarity threshold (0.5)
    - Metadata filters (document_id, user_id)
  - Return chunks with similarity scores
- Add relevance scoring normalization

**Step 5.5: BM25 Keyword Search**
- Create BM25 index builder:
  - Load all chunks for a document
  - Tokenize text (lowercase, remove stopwords)
  - Build BM25 index using rank-bm25
  - Store index in memory or pickle file
- Implement BM25 search function:
  - Accept query and document filter
  - Tokenize query
  - Get BM25 scores for all chunks
  - Return top K results with scores
- Add index update mechanism for new documents

**Step 5.6: Hybrid Retrieval System**
- Create unified retrieval function:
  - Accept query, document_ids, top_k
  - Run semantic search and BM25 search in parallel
  - Normalize scores to 0-1 range:
    - Semantic: already normalized (cosine similarity)
    - BM25: divide by max score in results
  - Combine scores with weights:
    - Final score = 0.7 * semantic_score + 0.3 * bm25_score
  - Re-rank results by combined score
  - Remove duplicates (same chunk_id)
  - Return top K unique chunks with sources
- Add configuration for adjustable weights
- Implement result deduplication strategy

**Step 5.7: Context Window Management**
- Create function to prepare context from retrieved chunks:
  - Accept chunks and token limit (default 3000)
  - Sort chunks by relevance and document order
  - Concatenate chunk texts with separators
  - Include source references (page numbers)
  - Truncate if exceeds token limit
  - Add document titles and metadata
- Format context for LLM consumption

**Step 7.3: LLM-Based Quiz Generation**

**Prompt Template for Question Generation:**
```
You are an expert quiz creator. Generate {num_questions} multiple-choice questions from the provided content.

CONTENT:
{document_chunks}

REQUIREMENTS:
- Difficulty level: {difficulty}
- Each question must have exactly 4 options (A, B, C, D)
- Only ONE option should be correct
- Incorrect options should be plausible but clearly wrong
- Provide a clear explanation for the correct answer
- Questions should test understanding, not just memorization

DIFFICULTY GUIDELINES:
- EASY: Direct recall, definitions, basic facts
- MEDIUM: Application, comparison, analysis
- HARD: Synthesis, evaluation, complex scenarios

Return questions in this JSON format:
{
  "questions": [
    {
      "question": "question text",
      "options": ["option A", "option B", "option C", "option D"],
      "correct_answer": 0,  // index of correct option
      "explanation": "why this is correct and others are wrong",
      "difficulty": "EASY"

  ]
}
```

**Generation Function:**
- Accept document_id, difficulty, num_questions
- Retrieve and prepare document chunks
- For MIXED difficulty:
  - Generate equal distribution of EASY, MEDIUM, HARD
  - Call API separately for each difficulty level
- Construct prompts with content and requirements
- Call OpenAI/Groq API with JSON mode enabled
- Parse and validate JSON response
- Ensure question quality (unique, grammatical)
- Store questions in database

**Step 7.4: Question Validation**

## **COST ESTIMATION & OPTIMIZATION**

### **API Costs (Approximate)**

**OpenAI Pricing:**
- GPT-3.5-turbo: $0.0015/1K tokens (input), $0.002/1K tokens (output)
- GPT-4: $0.03/1K tokens (input), $0.06/1K tokens (output)
- Embeddings (text-embedding-3-small): $0.00002/1K tokens
- Whisper: $0.006/minute

**Expected Monthly Costs (100 active users):**
- Embeddings: ~$5-10 (one-time per document)
- Chat (GPT-3.5): ~$20-50
- Quiz Generation (GPT-4): ~$30-60
- Speech-to-text: ~$10-20
- **Total: $65-140/month**

**Free Tier Alternatives:**
- **Groq**: Free tier with rate limits (llama3-70b, mixtral)
- **HuggingFace Inference API**: Free tier available
- **Local models**: Via Ollama (no API costs, requires GPU)

**Optimization Tips:**
- Cache embeddings (never regenerate)
- Cache common queries
- Use GPT-3.5 for chat, GPT-4 only for quiz generation
- Implement user limits (messages per day)
- Use shorter context windows when possible
- Batch API calls
